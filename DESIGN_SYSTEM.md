# Awto Design System

Generated by `/ui-ux-pro-max` on 2026-05-15 for product type *"browser extension developer tool minimal trustworthy productivity"*. Persisted for hierarchical retrieval across sessions. Page-specific overrides live in `design-system/pages/`.

## Pattern

**Minimal Single Column**

- Single CTA focus per screen
- Large typography
- Generous whitespace
- No nav clutter
- Mobile-first (still applies to a 400px-wide popup)

CTA placement: center, large button.
Section order on any screen: hero/title → short description → benefit bullets (3 max) → CTA → footer.

## Style

**Micro-interactions**

- Small animations (50–100ms hover)
- Gesture-based / tactile feedback
- Contextual interactions, subtle but responsive
- Best for: productivity tools, consumer apps, interactive components
- Mode support: Light ✓ full, Dark ✓ full
- Performance: excellent
- Accessibility: good

## Color Tokens

```css
:root {
  --color-primary:      #1E293B;  /* slate-800 */
  --color-on-primary:   #FFFFFF;
  --color-secondary:    #334155;  /* slate-700 */
  --color-accent:       #22C55E;  /* green-500 — the "Fill" CTA */
  --color-background:   #0F172A;  /* slate-900 */
  --color-foreground:   #F8FAFC;  /* slate-50 */
  --color-muted:        #272F42;
  --color-border:       #475569;  /* slate-600 */
  --color-destructive:  #EF4444;  /* red-500 */
  --color-ring:         #1E293B;
}
```

Theme feel: dark, cinematic, technical, precision, clean. Code-dark + run-green.

Both light and dark must be designed together — don't infer one from the other. Dark mode uses desaturated tonal variants, not inverted colors. Test contrast independently per theme.

## Typography

- **Heading + Body**: `Inter` (weights 300, 400, 500, 600, 700)
- **CSS Import**: `@import url('https://fonts.googleapis.com/css2?family=Inter:wght@300;400;500;600;700&display=swap');`
- **Type scale** (consistent across all surfaces): 12 / 14 / 16 / 18 / 24 / 32
- **Body minimum**: 16px (avoids iOS auto-zoom — also helps on Retina Macs)
- **Line-height**: 1.5 body, 1.2 headings
- **Letter-spacing**: respect Inter defaults; do not tighten body
- **Tabular numerals** (`font-variant-numeric: tabular-nums`) on any list of values to prevent layout shift

## Iconography

- **Lucide SVG** only. No emojis used as icons.
- Single stroke width across the product (1.5px).
- Sizes from tokens: `icon-sm` 16px, `icon-md` 20px, `icon-lg` 24px.
- Filled vs outline: pick one per hierarchy level; never mix at the same level.
- Tap area expands via padding/hitSlop to ≥44×44px even when the visual icon is smaller.

## Motion

- Duration: 150–300ms for micro-interactions; complex transitions ≤400ms.
- Easing: ease-out for entering, ease-in for exiting.
- **Exit faster than enter** (~60–70% of enter duration).
- Animate only `transform` and `opacity`. Never width/height/top/left.
- Respect `prefers-reduced-motion` — reduce or disable.
- Every animation must convey cause-effect, not decoration.
- Modals / sheets animate from their trigger source (scale + fade).
- Button press: subtle scale (0.97) on press, restore on release.

## Layout

- Popup width: 400px (Chrome popup max ~800px, but narrower feels less imposing).
- Options page: max-w-2xl centered.
- Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 / 48 (4pt rhythm).
- Z-index scale: 0 / 10 / 20 / 40 / 100 / 1000.
- Borders: 1px solid `--color-border` for separation, never decorative.
- Radius: 6px controls, 8px cards, 12px modals.
- Elevation: one consistent shadow scale. Cards use no shadow (border only). Modals use `0 8px 24px rgba(0,0,0,0.4)`.

## Forms (the heart of this product)

- Visible label per input (not placeholder-only).
- Helper text persistent below complex inputs.
- Inline validation on **blur**, not on every keystroke.
- Errors shown inline below the field, in `--color-destructive`, with a recovery path stated.
- Required indicator: subtle asterisk; never rely on red alone.
- Use semantic input types (`email`, `tel`, `number`, `date`) — triggers the right keyboard on touch devices.
- Autocomplete attributes set correctly (`autocomplete="given-name"`, etc.) so the *browser's own autofill* also works — we don't fight the OS.
- Disabled state: opacity 0.4 + `cursor: not-allowed` + semantic `disabled` attribute.
- Submit button: disabled during pending; spinner replaces label text.

## Awto-Specific Screen Designs

### Popup (the confirmation UI)

The popup opens after the user clicks the toolbar icon on a page with a form.

**Layout** (top to bottom):
1. **Header bar** (48px): app name "Awto" on the left in 14px medium, status indicator on the right (green dot = ready, amber = local LLM unavailable, red = error).
2. **Will fill section**: collapsible card. Header reads "X fields ready" with a chevron. Body is a 2-column table — `Label` → `Value`. Each value is inline-editable (click to focus, blur to commit). Confidence < 0.85 fields have a small amber dot before the label.
3. **Needs your input** section (only if missing fields exist): header reads "Tell us X things" in `--color-accent`. Below: one row per missing field, each with a label and a text input. The LLM-generated `promptText` shows as the field's helper text.
4. **Skipped** section: collapsed by default. Header "X skipped". Expanding shows the field labels and the LLM's `reason` per row.
5. **Footer bar** (fixed, 64px): single full-width green **Fill** button. Cancel as a smaller secondary text-button to the left.

**Empty state** (no form detected): center-aligned message "No form on this page" with a softer follow-up "Awto activates when there's something to fill."

**Loading state** (LLM thinking): skeleton rows in the Will-fill section, animated shimmer at 1.5s loop. Use Lucide `loader-2` spinning if the LLM call exceeds 2s.

**Error state** (both local and cloud failed): inline error card with the failure reason in plain English and a "Try again" button.

### Options Page

Tabbed layout, three tabs:

1. **Profile** — friendly form view with sections grouped by concern (Identity, Contact, Address, Work). Each field with its current value, a clear label, and a delete button. "Add custom field" button at the bottom of each section. A "View raw JSON" toggle reveals an editable textarea for power users.
2. **LLM** — two cards:
   - **Local (Ollama)**: URL field (default `http://localhost:11434`), model name field (default `llama3.2`), a **Test connection** button that pings `/api/version`. Status badge shows last test result.
   - **Cloud (Anthropic)**: API key input (password-masked with show/hide toggle), model picker (default `claude-opus-4-7`), fallback toggle (on by default).
   - Footer note: "Awto tries local first. Cloud is only used when local is uncertain. Your API key never leaves this device."
3. **About** — version, links to docs, license, GitHub. No telemetry settings because there is no telemetry.

## Accessibility Floor

- All text ≥4.5:1 contrast.
- Buttons ≥7:1 contrast on accent color.
- Focus rings: 2px solid `--color-accent`, offset 2px — visible on every interactive element.
- All icon-only controls have `aria-label`.
- Tab order matches visual order; no skip without `<a href="#main">` skip link.
- Form errors announced via `aria-live="polite"`.
- After submit failure, auto-focus the first invalid field.
- Respect `prefers-color-scheme` and `prefers-reduced-motion`.

## Anti-Patterns to Avoid

- ❌ Complex onboarding (multi-step wizard on first launch). One screen: "Add your details" + an inline form.
- ❌ Slow perceived performance — show skeletons within 300ms.
- ❌ Emojis as icons.
- ❌ Hover-only affordances.
- ❌ Placeholder text as the only label.
- ❌ Mixing filled and outline icons in the same row.
- ❌ Errors only at the top of the form.
- ❌ Auto-fill without confirmation. **Always** confirm.
